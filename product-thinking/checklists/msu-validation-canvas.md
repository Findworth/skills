# 最小可售单元（MSU）验证画布

> **何时用本清单**：你有一个 Skill / AI 工具 / 微产品的想法，**写代码之前**，先把它填进这张画布。填不出来 = 还没想清楚 = 别开发。

## 适用对象
- AI Skill 创业者、独立开发者
- 想做副业变现的内容/职场人
- 任何想用"小产品验证商业假设"的人
- PMF 验证期的早期团队

---

## 核心心法

> **MVP 验证「产品成立」，MSU 验证「商业成立」。**
> 不是问"能不能用"，是问"有没有人愿意付钱"。

---

## 清单本体（填空式画布）

### 第一部分：MSU 定义画布

```
┌─────────────────────────────────────────────────┐
│  我的 Skill 名称：______________________________ │
├─────────────────────────────────────────────────┤
│  ① 对应的高频付费场景：                            │
│     ___________________________________________ │
│     （必须是"用户已经在花钱解决的事"，不是"如果有就好"） │
├─────────────────────────────────────────────────┤
│  ② 用户原本怎么解决：                              │
│     ___________________________________________ │
│     （写得出"原本方案"才说明需求真实存在）            │
├─────────────────────────────────────────────────┤
│  ③ 我的输入字段（理想 ≤ 1 个）：                    │
│     ___________________________________________ │
│     （多于 3 个字段直接打回重做）                    │
├─────────────────────────────────────────────────┤
│  ④ 我的输出形式（必须 done-for-you）：              │
│     ___________________________________________ │
│     （不能是"建议"、"参考"、"3 个方向"）            │
├─────────────────────────────────────────────────┤
│  ⑤ 价格区间：                                     │
│     ___________________________________________ │
│     （写出你愿意付的价格 × 2，那才是市场价）         │
├─────────────────────────────────────────────────┤
│  ⑥ 第一个验证渠道：                                │
│     □ 发内容（朋友圈/小红书/即刻）                  │
│     □ 人工替代（自己手动帮 5-10 个人做）             │
│     □ 预售（先收钱再做）                            │
├─────────────────────────────────────────────────┤
│  ⑦ 验证通过的标准：                                │
│     ___________________________________________ │
│     （如：10 人主动询问 / 3 单预付 / 1 人复购）       │
└─────────────────────────────────────────────────┘
```

### 第二部分：自检清单

- [ ] ① 场景是"已经在花钱"的，不是"应该愿意花钱"的
- [ ] ② 能说清楚用户原本的替代方案（不能是"原本没有"）
- [ ] ③ 输入字段 ≤ 3 个，理想是 1 个
- [ ] ④ 输出是"成品"，用户拿到直接用，不再加工
- [ ] ⑤ 价格定得让自己觉得"有点不好意思要"——那才接近市场愿付价
- [ ] ⑥ 选了一个 ≤ 3 天内可执行的验证渠道
- [ ] ⑦ 验证标准是数字，不是"反应不错"

```
├─────────────────────────────────────────────────┤
│  ① 场景：互联网/求职转行的人改简历                  │
│     （已有付费市场：猎头服务、LinkedIn 修改、淘宝代写）│
├─────────────────────────────────────────────────┤
│  ② 原本怎么解决：                                  │
│     - 自己改 3-5 版（耗时 5+ 小时）                 │
│     - 花 200-500 元请猎头/HR 朋友看                │
│     - 淘宝 50-300 元代写                          │
├─────────────────────────────────────────────────┤
│  ③ 输入字段：上传一份简历（PDF/Word）                │
│     （仅 1 个输入）                                │
├─────────────────────────────────────────────────┤
│  ④ 输出：一份重新改写、按大厂 STAR 模板重排的         │
│     Word 简历，附 5 条修改说明，可直接投递          │
│     （done-for-you，不是"几条建议"）              │
├─────────────────────────────────────────────────┤
│  ⑤ 价格区间：19.9 元 / 单                          │
│     （锚定淘宝 50 元，砍半引流）                    │
├─────────────────────────────────────────────────┤
│  ⑥ 验证渠道：朋友圈 + 即刻 + 小红书各发一条          │
│     "免费帮 3 位粉丝优化简历，评论区扣 1"             │
├─────────────────────────────────────────────────┤
│  ⑦ 验证标准：                                      │
│     - 3 天内 ≥ 10 人主动私信要测试，立项；           │
│     - 同期 ≥ 1 人愿意付 9.9 预订正式版，启动开发；    │
│     - 私信 < 3 人，砍掉换方向。                     │
└─────────────────────────────────────────────────┘
```

## 每条说明（详解）

### ① 高频付费场景
**为什么问这个**：变现 ≠ 解决问题，变现 = 解决"用户已经在花钱解决的问题"。如果你的场景没人花钱，就算你做出来也只能免费用。
**怎么算通过**：你能举出至少 2 种现有付费替代方案（淘宝、SaaS、咨询、培训）。
**反模式**：写"帮人变得更高效"——太泛、没人按这个搜索付费。

### ② 用户原本怎么解决
**为什么问这个**：能说清楚"原本方案"，说明需求真实；说不清，要么是伪需求，要么是用户根本没意识到。
**怎么算通过**：替代方案具体到行为（不是"自己做"，而是"打开 Excel 复制粘贴 30 分钟"）。
**反模式**：写"原本只能将就"——这是你的想象，不是用户的现实。

### ③ 输入 ≤ 1 个
**为什么问这个**：Google 干掉 Yahoo 靠的就是一个搜索框。每多一个输入框，流失指数级上升。
**怎么算通过**：上传一份文件 / 输入一个词 / 选一个选项。
**反模式**：让用户填"详细背景、目标受众、风格、字数、语气、目的"——这是表单，不是工具。

### ④ Done-for-you 而非 DIY
**为什么问这个**：教你怎么做 vs 替你做完，付费意愿差 5-10 倍。
**怎么算通过**：输出是"成品"，用户复制即用，不需要二次创作。
**反模式**：输出"3 个方向供你参考"——这等于把工作甩回给用户。

### ⑤ 价格区间
**为什么问这个**：定低了赚不到钱，定高了无人付费。最好的锚点是"现有替代方案的 1/3 到 1/2"。
**怎么算通过**：定价后还能感觉"有点利润"，而不是"白嫖"。
**反模式**：免费 + 后期变现——除非你有大资本，否则免费用户的转化率很低。

### ⑥ 验证渠道
**为什么问这个**：验证 ≠ 开发。在你写一行代码之前，先用最便宜的方式确认需求存在。
**怎么算通过**：3 天内可启动，0 元成本（朋友圈 / 即刻 / 人工替代）。
**反模式**：先开发 3 个月，上线再验证。

### ⑦ 验证通过的数字标准
**为什么问这个**："反响不错"是自欺欺人，必须是数字。
**怎么算通过**：标准写明"≥ X 人主动行为"，X 是你提前承诺自己的。
**反模式**："朋友说不错，我觉得可以做"——朋友不是用户。
